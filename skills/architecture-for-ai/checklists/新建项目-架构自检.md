# 新建项目 · 架构自检

**怎么用**：在写第一行业务代码**之前**过一遍 A 段；每个功能合入前过 B、D 段；发版前过 C 段。
每条只需回答"是 / 否 / 不适用"，答"否"的必须给出一个**具体动作**（不是"注意一下"）。
**只看本清单即可执行，不必读正文。**

---

## 0 先填这张卡（不填完不要开始写代码）

```
项目名：
唯一可写目录：            （将在其中工作的那一个目录，写绝对路径或明确的仓库根）
是否有版本控制：          是 / 否     若否 -> 立刻做 G2-1～G2-3（备份到被改目录之外 + 记前后哈希 + 标注"弱等价"）
逻辑层放在哪：            （可被多个入口共用的模块目录名）
入口有哪几个：            （界面 / 命令行 / 服务 / 机器人 / 定时任务，逐个列出）
数据放在哪、谁写它：       （目录 + 唯一写盘函数名）
高频动作 top3：            （每天会做很多次的那三件事）
产物是否需要逐字节可复现：需要 / 不需要（不需要要写理由）
```

## A 开始写代码前（分层与单源）

- [ ] **A1-1** 我写下了一条命令规则："业务判断只允许出现在 `<逻辑层目录>`，其他目录出现 `if` 判断业务规则即为缺陷。"
- [ ] **A1-2** 每个入口都能回答："删掉这个入口，逻辑是否仍然完整？"（应回答"是"）
- [ ] **A2-1** 我写下了允许的依赖层序（例如 入口 → 逻辑 → 数据），并且它能被一条搜索命令检查（底层目录的引用里不出现上层名字）。
- [ ] **A2-2** 底层需要上层信息时，我的做法是**传参/回调**，不是反向引用。
- [ ] **A3-1** 我列出了"易腐事实"清单（数量、清单、字段、版本号、规则条数），每一项都指定了**唯一出处**。
- [ ] **A3-2** 需要引用这些事实的其他位置，只放**指针**，不复制内容。
- [ ] **A3-3** 我把"同一事实的第二处表达"定义为缺陷，并知道怎么搜到它（搜关键字/搜数字）。

## B 每个功能合入前（可机械取证的结构前提）

- [ ] **B1-1** 这个功能声明的不变量，我都能指出**一条命令**判定它，且以退出码表达成败。
- [ ] **B1-2** 我能回答："人按原有习惯操作，得到的是否还是设计意图？"——并据此检查默认路径行为是否**逐字未变**。
- [ ] **B1-3** 新能力是 opt-in 的：不加新开关时，输出/行为与改动前相同。
- [ ] **B2-1** 核心入口能在**同一进程内**被调用，不需要起子进程、不需要管道 stdio。
- [ ] **B2-2** 入口不调用"立即结束进程"的 API（会连带杀死宿主），退出码状态进出都被隔离。
- [ ] **B2-3** 如果我提供了同步入口，存在一条可机械检查的约束保证它不会静默半途返回；违反时**报错不降级**。
- [ ] **B2-4** 我**先**写了对外契约快照（退出码 + 输出文本），再改内部实现。
- [ ] **B3-1** 有一条不依赖人眼/鼠标的验收路径（无头或离屏）。
- [ ] **B3-2** 尺寸/分辨率是**显式固定**的，不依赖框架默认值。
- [ ] **B3-3** 无头状态下产物仍然有效（不是空白/旧帧），并有一条断言守住它。
- [ ] **B3-4** "等渲染/等就绪"靠的是明确条件（若干帧/状态标志），不是固定 sleep。
- [ ] **B4-1** 判定/转换/校验逻辑能在"目录不存在"的情况下被调用（不需要 I/O、时钟、网络）。
- [ ] **B4-2** I/O、时钟、随机、环境都是从参数传入的。
- [ ] **B5-1** 同一输入跑两次，产物**逐字节相同**（给出比对方式：哈希/逐字节 diff）。
- [ ] **B5-2** 若不逐字节相同，我已**逐个列出非确定来源**（时间串、随机 id、并发顺序、默认值、动画中间态、字体/缩放）。
- [ ] **B5-3** 非确定来源已**先消除**；只有在消除后仍不可复现时，才允许放宽判据，且放宽理由写进了文档。

## C 发版前（上下文成本）

- [ ] **C1-1** "该读哪一部分"有专门入口（能只回答一个窄问题），不需要先读全量。
- [ ] **C2-1** 输出粒度 >= 3 档，且每一档都写明了"丢了什么"。
- [ ] **C3-1** 高频动作的读取量有**上界**，并被写下来/被测试。
- [ ] **C3-2** 这个上界不会随项目年龄增长（历史/归档/日志不参与常规读取）。
- [ ] **C4-1** 变更历史有窄查询入口（按关键词/段号），查不到时输出**指路**到归档位置。

## D 涉及写盘时（并发与原子性）

- [ ] **D1-1** 写盘出口只有一个函数，我搜过裸写文件的调用并确认没有旁路。
- [ ] **D1-2** 这个函数内部顺序是：校验 → 版本检查 → 原子写。
- [ ] **D2-1** 读操作返回内容指纹；写操作要求声明"我读到的是哪一版"。
- [ ] **D2-2** 指纹是**内容哈希**，不是修改时间/文件大小。
- [ ] **D2-3** 指纹不匹配时**拒绝写入**，并报出两侧版本。
- [ ] **D2-4** **所有**写入口（界面保存、命令行、服务接口）共用同一个闸门——没有例外。
- [ ] **D2-5** 我能区分"我把它清空了"与"我没见过这个字段"（不能靠猜，要靠指纹/版本）。
- [ ] **D3-1** 写盘 = 同目录临时文件 → 落盘 → 重命名；中断只留临时文件，正式文件保持原样。
- [ ] **D3-2** 失败路径会清理临时文件。
- [ ] **D4-1** 可派生的事实是**生成**的，不是手写的；生成物头部有"勿手改 + 重新生成方式"。
- [ ] **D4-2** 有一条检查"生成物是否过期"（逐字比对）。

## E 新增任何文件/目录时

- [ ] **E1-1** 我知道根目录白名单、顶层目录白名单、工作产物区各自允许什么。
- [ ] **E1-2** 新产物已登记到其中一处（白名单 / 忽略清单 / 真值 / 生成物）。
- [ ] **E1-3** 已有扫描器/收集器/门禁不会把这个新产物当成输入（我确认过它们的包含规则）。
- [ ] **E1-4** 违反时的报错信息里写了"该放哪"（报错即指路）。
- [ ] **E2-1** 这条规则出现在**执行这个动作的人此刻必然会看到**的地方（命令输出/文件头/报错/新会话第一屏）。
- [ ] **E2-2** 我没有把规则只写在"需要人主动去读的长文档"里。

## F 每次提交前

- [ ] **F1-1** 失败不会被静默吞掉；跳过/降级会显式打印"跳过了什么、为什么"。
- [ ] **F1-2** "无法判定"与"通过"在输出上可区分（不是同一个颜色/同一个退出码）。
- [ ] **F2-1** 所有文本文件是 UTF-8 **无 BOM**，换行统一。
- [ ] **F2-2** 我没有用"读原文再写回"的 shell 往返来改文本（会引入 BOM 或乱码）。
- [ ] **F2-3** 临时产物也按正式产物对待（它可能被扫描/入库/被下一步读取）。
- [ ] **F3-1** 我新增的检查只锁**可机械判定**的事。
- [ ] **F3-2** 主观项（命名、优雅、文案）只是人工确认清单，没有做成硬门禁。
- [ ] **F3-3** 我没有给"看起来该测、其实采集前被清空/不可判定"的目标加断言。

## G 动手改之前

- [ ] **G1-1** 我确认了这份目录**能不能回滚**（判断标准是"能不能回到上一版"，不是"有没有 .git 目录"）。
- [ ] **G2-1** 若不能回滚：我把可整体回滚的备份导出到**被改目录之外**。
- [ ] **G2-2** 我记录了改动前后的哈希。
- [ ] **G2-3** 我在文档里写明了"这是弱等价、不是等价"，并列出了它缺什么（分支/二分/原子整批回滚/区分作者）。
- [ ] **G2-4** 我的备份不是原件同目录的第二份副本，也不依赖手工同步（多副本 + 单向同步必丢工作）。

## H 每次有人提"我们应该……"时

- [ ] **H1** 这次改动没有新增第二份实现（没有"新写一套，旧的慢慢淘汰"）。
- [ ] **H2** 核心能力没有放进"兼容层/过渡层"。
- [ ] **H3** 我没有给最高频的动作加新成本；新能力是 opt-in 且不加开关时行为逐字不变。
- [ ] **H4** 这次改动有**真实事故或实测**作为依据，不是"看起来更严谨"。
- [ ] **H5** 我没有依赖"没人会碰"；不可逆或可能被并发碰的地方做了**显式复位/隔离**。
