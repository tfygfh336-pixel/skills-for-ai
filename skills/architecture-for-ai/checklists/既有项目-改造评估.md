# 既有项目 · 改造评估

**怎么用**：这是**只读评估**，用来决定"该不该动、先动哪里、动完凭什么说变好了"。
按阶段走，不要跳到最后。每阶段产出**具体条目**（文件名/命令/数字），不产出形容词。
**只看本清单即可执行，不必读正文。**

> 铁律：本清单的每一条都是"先取证，再动手"。**任何"改动/替换"动作前，先断言锚点唯一命中**
> （搜到的命中数为 0 或 >1 就停手，不要"猜一个最像的"）。

---

## 阶段 0 · 取证（只读；不改任何文件）

- [ ] **0-1 范围**：写下本次评估覆盖的目录与**明确不覆盖**的目录（后者写上原因）。
- [ ] **0-2 回滚能力**：确认是否**真能**回到上一版。判断标准是"能回滚"，不是"有 .git"。
      否 ⇒ 立即执行 G 段：导出被改目录之外的备份 + 记录当前哈希 + 在文档里标注"无回滚（外部阻塞）"。
- [ ] **0-3 基线哈希**：对**本阶段要读的关键文件**取哈希并留存（作为"没被改过"的证据）。
      若要求"只读"，这是唯一的证明方式。
- [ ] **0-4 写者清单**：列出所有会写这份数据的人与进程（人界面 / 命令行 / AI / 定时任务 / 同步工具）。
      写不出 ⇒ 先查（看进程、看脚本、看文档），因为 D 段的闸门设计依赖它。
- [ ] **0-5 高频动作清单**：列 top3 高频动作，并记下各自当前的成本（步数、秒数、字节数）。
      **这是改造前后对比的基座；没有它就没有"变好了"的证据。**

## 阶段 1 · 找结构病灶（逐条回答"是/否 + 证据"）

- [ ] **1-1 第二处表达**：搜同一个判定表达式/同一份清单/同一个数字，是否存在两处**完整写出**？
      证据：文件:行 + 另一处文件:行。
- [ ] **1-2 回边**：依赖图里有没有回边（底层引用了上层）？证据：引用行。
- [ ] **1-3 壳里的业务判断**：入口层是否出现业务规则判断？证据：行。
- [ ] **1-4 单命令判定**：随机挑三条"不变量"，各问"一条命令能不能判定"。列出现在**做不到**的条目。
- [ ] **1-5 验证成本**：跑一次完整验证要多久？其中多少是**进程冷启动/环境准备**（可被进程内化消掉的）？
- [ ] **1-6 无头能力**：不开界面/不给人看，能不能验收？不能 ⇒ 记下卡在哪一步。
- [ ] **1-7 纯粹性**：核心逻辑里有多少函数**必须**先有 I/O 才能测？列出来。
- [ ] **1-8 确定性**：同一输入跑两次产物是否逐字节相同？不同 ⇒ 记录哈希与差异位置。
- [ ] **1-9 读取成本**：高频动作各读多少字节？成本是否随项目年龄增长（历史/日志/归档参与读取）？
- [ ] **1-10 粒度档位**：输出有几档？是否存在"想要中间粒度只能读全量"的缺口？
- [ ] **1-11 写盘出口**：搜所有写文件调用，几个不经过唯一写盘函数？
- [ ] **1-12 并发闸门**：读回内容指纹了吗？写回时校验盘上版本吗？界面与命令行是否共用同一闸门？
- [ ] **1-13 原子性**：写盘是否 tmp → 落盘 → rename？有没有直写？
- [ ] **1-14 生成物**：可派生的事实里有多少是手写的？有没有"生成物过期"检查？
- [ ] **1-15 登记面**：现在新增一个文件，会被谁判非法？报错里有没有写"该放哪"？
- [ ] **1-16 静默失败**：随机挑三个错误路径，看是否都会响亮失败（退出码 + 明确文本）。列出静默的。
- [ ] **1-17 编码**：抽样检查文本文件的 BOM 与换行是否统一。列出不统一的目录。
- [ ] **1-18 不可判定被硬锁**：有没有断言锁住"采集前被清空/本质主观"的目标（会永远判红）？
- [ ] **1-19 规则可见性**：挑 3 条规则，问"执行者在动作现场能看到吗"。看不到的列出来。
- [ ] **1-20 副本**：存在第二份副本/软链/手工同步吗？**它们是否已经双向发散？** 列出差异条目。

## 阶段 2 · 排优先级（先算收益，再排）

- [ ] **2-1** 把阶段 1 的病灶逐条写"损害类别"：① 静默丢数据；② 结论错误（让人误判）；③ 不可逆；
      ④ 高频动作成本；⑤ 后续改动成本；⑥ 只是不好看。
      **前四类优先；第⑤类次之；第⑥类本次不做。**
- [ ] **2-2** 对每条写"单次节省 × 频次"（能用数字就用数字；不能用数字就写"未量化"，不要编）。
- [ ] **2-3** 标出**外部阻塞项**（例如版本控制在环境层不可得）——它们不进本次改动，但要进文档的"已知缺口"。
- [ ] **2-4** 排序并写下**本次不做**的清单及其理由（不做也要留痕，否则下次会重新讨论）。

## 阶段 3 · 改造前（每个改动执行前必答）

- [ ] **3-1 锚点唯一性**：待改文本在目标文件里的命中数**恰好为 1**；否则停手并报告（不要凭猜测替换）。
- [ ] **3-2 契约快照**：若改动涉及对外行为（退出码、输出文本、接口签名、文件格式），
      **先**写下快照（逐字节或结构化），改完用它证明"行为等价"。
- [ ] **3-3 对照基线**：记录改动前的表现（产物哈希、耗时、输出字节数），否则无法证明变好。
- [ ] **3-4 连带清单**：把"改 A 必须连带改 B"写成清单（含注册表/文档/白名单/忽略清单/计数）。
      这份清单本身应是可机械检查的；若不能，至少先手写并逐项打勾。
- [ ] **3-5 备份**：无可回滚能力时，先导出备份到被改目录之外，并记前后哈希。
- [ ] **3-6 默认路径不变**：写下"不加新开关时，行为应与改动前逐字相同"的验证方式。
- [ ] **3-7 反向验收**：若本次不应改动某外部工程/某目录，**先取其哈希**，结束后再取一次对比。

## 阶段 4 · 改造中（顺序即纪律）

- [ ] **4-1** 先做"消除非确定来源"，**不要**先放宽判据。
- [ ] **4-2** 先做"进程内可调用入口"，**但先有契约快照**；进程内路径与子进程路径要跑对照断言。
- [ ] **4-3** 版本闸门要**一次覆盖所有写入口**（先补漏的那个入口，别只补一个字段）。
- [ ] **4-4** 新产物**同批**登记（白名单/忽略清单/真值/生成物），不要留到下次。
- [ ] **4-5** 新检查只锁可机械判定项；主观项只做提示。
- [ ] **4-6** 任何"顺手清理"都不做——它会让"变红"无法归因（这正是改造中最容易自伤的地方）。

## 阶段 5 · 改造后（拿证据说话）

- [ ] **5-1** 契约快照逐字节比对通过（或列出**每一处**差异并说明是否为设计意图）。
- [ ] **5-2** 判据核对：不是"测试是否还绿"，而是"**人按原有习惯操作得到的是否还是设计意图**"；
      给出默认路径行为未变的证据。
- [ ] **5-3** 确定性：改造后同输入跑两次，逐字节相同（给哈希）；若仍不同，列出剩余非确定来源。
- [ ] **5-4** 成本对比：与阶段 0-5 的基线逐项对比（耗时/字节数/步数），写出实际数字。
- [ ] **5-5** 结构病灶复查：回到阶段 1，对"原本为否"的条目重新回答"是/否 + 证据"。
- [ ] **5-6** 未解决项：把没做的、做不了的、不确定的**显式写下来**（含外部阻塞项），
      **不要**用"基本完成"带过。
- [ ] **5-7** 反向验收：对被要求"只读"的目录重新取哈希，与 0-3 对比并给出结果。
- [ ] **5-8** 诚实标注：若采用弱等价手段（备份 + 哈希代替版本控制），在文档里写明**这是弱等价、不是等价**。

## 阶段 6 · 常见自伤（改造时最容易犯）

- [ ] **6-1** 没有基线就宣称"变快了"。
- [ ] **6-2** 先放宽判据再谈确定性（把回归藏进噪声）。
- [ ] **6-3** 改完顺手重构，导致变红时无法归因。
- [ ] **6-4** 只给一个写入口加版本闸门（等于没加）。
- [ ] **6-5** 新增产物未登记，留到下次在别处爆红。
- [ ] **6-6** 把不可判定项做成硬门禁（要么长期假红，要么被迫永远通过）。
- [ ] **6-7** 用另一份副本"备份"（同目录或手工同步）——多副本 + 单向同步必丢工作。
- [ ] **6-8** 以"更严谨"为理由引入抽象/门禁，却拿不出事故或实测。
- [ ] **6-9** 改了被要求只读的目录（**没有事前哈希就无法自证**）。
