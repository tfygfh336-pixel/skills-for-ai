# 新建项目 · 文档架构自检

**怎么用**：在一个工程**刚开始**（或刚决定"要长期做下去"）时，按阶段走一遍。每步产出**具体条目**（文件名 / 命令 / 一句话），不产出形容词。
**只看本清单即可执行，不必读正文**（正文是 `SKILL.md`；机制与模板在 `REFERENCE.md`）。

> **该不该用这份清单**：工程**还没有**文档、或只有一份刚写的入口文档 ⇒ 用这份。
> 若已有过期文档/散落草稿/漂移过的清单 ⇒ 先用 `既有项目-文档架构改造评估.md` 的阶段 0 取证，
> 再回到本清单的阶段 1–5 重建（**先取证 → 再重建 → 用同一把尺子验收**）。

> 铁律：**不因为"规范"而建东西**。每加一份文档、每个目录、每条门禁，都要能回答"它降低了哪个失败"。
> 新项目最常见的错不是"文档太少"，而是"第一天就抄来一套用不上的文档结构"。

---

## 阶段 0 · 先定判据（10 分钟，不写文件）

- [ ] **0-1 写下"接手四问"的预期答案**：① 现在什么状态、什么没做完？② 我这类任务按什么步骤做？③ 写文件有什么禁令？④ 凭什么算做完？
      **答案是空的 ⇒ 继续往下做；答案是"不知道" ⇒ 这正是你要建的东西。**
- [ ] **0-2 定"第一屏"是哪一份文件**：新会话（人或 AI）必然会看到的那一份。若工程以 skill / 提示词方式被消费，
      第一屏就是 skill 正文；若以仓库方式被消费，第一屏通常是 `README` 顶部或 `AGENTS.md`/`CONTRIBUTING` 之类。
      **只允许一个第一屏**（两个 ⇒ 必然有一个过期）。
- [ ] **0-3 写下三类内容的**真实**归宿**（先写目录名，不建目录）：活跃文档放哪、归档放哪、工作产物放哪。
      小项目允许"归档与工作产物暂时同处一个目录"，但要在文档里写明"暂时"，并记下何时分。

## 阶段 1 · 最小文档集（先少后多）

- [ ] **1-1 逐份确认"这份现在就需要吗"**。一个 AI 迭代的小工程，起步通常只需要 4–6 份：
      | 文档 | 唯一理由 | 不该写 |
      |------|---------|--------|
      | 第一屏（触发与导航） | 何时用、从哪读起、接手 N 步 | 规则全表、命令清单 |
      | 规则（唯一权威） | 分级（门禁/铁律/约定）+ 强制方式 | 具体用法与架构理由 |
      | 变更记录 | 每次变更必写；未发布段 | 规划（那是路线图的） |
      | 路线图 / 在飞 | 什么还没做完（带证据指针） | 版本流水（那是变更记录的） |
      | 契约（数据/接口） | 字段、版本演进与兼容承诺 | 用法与理由 |
      | 架构与决策（可合并） | 分层、模块职责、**为什么这样设计** | 具体计数（指向基线文件） |
- [ ] **1-2 每份写头部元信息块**（`层 / 作用 / 不该写 / 更新方式`，见 `REFERENCE.md` §4.1）。
      **写不出"不该写什么" ⇒ 它和别的文档重叠**，先合并再继续。
- [ ] **1-3 定"接手 N 步"**写在第一屏（`REFERENCE.md` §4.5），顺序固定：没做完的 → 最近改的 → 这类任务怎么做 → 怎么算完 → 收尾。
- [ ] **1-4 定三处"唯一权威"**：规则在哪份、清单在哪份、数字在哪份（通常是生成物）。**其它地方只准写指针。**

## 阶段 2 · 三类归宿落地

- [ ] **2-1 建工作产物区**（唯一杂物区）：命名约定 `<YYYYMMDD>-<主题>/`；写进第一屏"默认不落盘，必须落盘走三条路"。
- [ ] **2-2 建归档目录 + 横幅约定**：归档文件**开头**必须带"历史归档（日期）：不是现状、勿据此改动"。
- [ ] **2-3 定白名单**：根目录允许哪些文件、顶层允许哪些目录。**把这份白名单写进报错文本**（报错即指路）。
- [ ] **2-4 定机器产物**：哪些文件是命令自动写的（可随时删、别手工编辑）。**写进工作产物区规则里**，免得后人猜。

## 阶段 3 · 单源与生成（先做最易腐的三样）

- [ ] **3-1 列出"会自己变化的事实"**：计数、体积、字段清单、命令清单、门禁条数、验证链步骤…… 每样指定**唯一来源**。
- [ ] **3-2 至少把两样做成生成物**：头部元信息 → 登记表；代码注册表 → 命令参考；真值脚本 → 基线文件。
      **生成物不得含时间/随机/当天状态**（否则无法逐字校验）。
- [ ] **3-3 挂"生成物过期"校验**：用同一渲染函数重算并逐字比对，红时报差异行 + 重生成命令。
- [ ] **3-4 给生成物写"请勿手改 + 怎么重生成"**在文件头部。

## 阶段 4 · 交接面

- [ ] **4-1 建"在飞 / 未收口"清单**：每条 `主题 · 当前结论 · 下一步 · 证据指针`；状态词表固定（未开始 / 在飞 / 外部阻塞 / 已收口）。
- [ ] **4-2 第一屏写明它与"未发布段"的分工**：一个记"没做完"，一个记"做完没发版"；只读一边会误判现状。
- [ ] **4-3 验证链留痕**：跑完写一份极小结果文件（时间/结论/失败项/各步耗时/版本），并在**跑之前打印一行**。
- [ ] **4-4 交接指针可校验**：先手工核对一遍"在飞"里的指针都存在（后续交给门禁）。

## 阶段 5 · 门禁（只做"已经发生过"的）

- [ ] **5-1 从这张清单挑 3 条起步**（按你目前最痛的）：登记与家门 / 悬挂登记 / 归档缺横幅 / 工作目录无状态 /
      导航不可达 / 契约缺字段 / 章节断号 / 生成物过期 / 易腐数字。
- [ ] **5-2 每条判定都注入一次违规证明它会红**，记下报文；撤销后**复绿**（撤销也要复核）。
- [ ] **5-3 每条判定写"能力边界"**（抓得住什么、抓不住什么）——不写边界，使用者会以为它万能。
- [ ] **5-4 把它们挂进一条命令**（一个入口跑完整链），并打印逐段耗时。
- [ ] **5-5 采不到真值 = 红**：把"跳过"与"通过"分成两个分支；**检查模式拒绝写入时，生成模式也必须拒绝**。

## 阶段 6 · 验收（不看文档数量，看接手成本）

- [ ] **6-1 量三条数**：第一屏到"下一步"要跳几次；常见任务各要读几份；一条命令能否回答"上次绿没绿"。
- [ ] **6-2 做一次只读接手演练**：找一个**零上下文**的会话（别的模型/新对话），只给它工程路径，
      要求它回答四问并**如实报告卡点**；记录留档。
- [ ] **6-3 卡点必须转化**：每条要么变成条目的补充，要么变成判定，要么**显式写下"决定不做"及理由**。
- [ ] **6-4 把演练写进节奏**：每个发版周期（或每轮迭代）至少一次；别只在"上线前"做。
