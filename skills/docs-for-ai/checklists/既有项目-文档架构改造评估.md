# 既有项目 · 文档架构改造评估

**怎么用**：这是**只读评估**，用来决定"该不该动、先动哪里、动完凭什么说变好了"。按阶段走，不要跳到最后。
每阶段产出**具体条目**（文件名 / 命令 / 数字），不产出形容词。
**只看本清单即可执行，不必读正文**（决策层是 `SKILL.md`，机制与模板在 `REFERENCE.md`）。

> **该不该用这份清单**：工程里**已有**过期文档 / 散落草稿 / 漂移过的清单 ⇒ 用这份（它从"取证"开始）。
> 若还没有文档 ⇒ 用 `新建项目-文档架构自检.md`。
> **两者常需拼用**：**本清单的阶段 0（取证）当基线 → 新建清单的阶段 1–5 重建 → 用本清单阶段 4 验收**。
> **不要跳过阶段 0** —— 没有基线就没有"变好了"的证据。

> 铁律：**先取证，再动手**。任何"重写/合并/替换"动作前，先断言锚点**唯一命中**
> （搜到的命中数为 0 或 >1 就停手，不要"猜一个最像的"）。
> 另：文档改造**天然是低风险改动**（改的是文本），但**它依赖的判据很容易看错** —— 所以本清单里"取证"占一半篇幅。

---

## 阶段 0 · 取证（只读；不改任何文件）

- [ ] **0-1 范围**：写下本次评估覆盖的目录，与**明确不覆盖**的目录（后者写原因）。
- [ ] **0-2 回滚能力**：确认**真能**回到上一版（"能回滚"≠"有 `.git` 目录"）。
      否 ⇒ 立即：把要动的文件导出到**被改目录之外**，记下当前哈希，并在文档里标注"无回滚（外部阻塞）"。
- [ ] **0-3 文档清单**：列出全部活跃文档 + 目录，标注：谁是入口/第一屏、谁是权威（规则/清单/数字）、谁是生成物、谁没人读。
      **"谁没人读"要给出证据**：最近一次被修改是什么时候、被谁引用过。
- [ ] **0-4 接手四问基线**：让一个**零上下文**的会话（新对话/别的模型）只读工程，回答：
      ① 现在什么状态、什么没做完？② 某类任务按什么步骤做？③ 写文件的禁令？④ 凭什么算做完？
      **如实记录它答不上来的部分**（这是本次评估最重要的基线，也是改完后的对照）。
- [ ] **0-5 接手成本基线**：第一屏到"下一步"要跳几次；常见任务各要读几份；一条命令能否回答"上次绿没绿"。
      **没有这组数就没有"变好了"的证据。**
- [ ] **0-6 历史与杂物普查**：数一下——归档目录里的文件是否都带"我是历史"的标记？
      工作产物区有多少目录/文件？其中多少还能判断死活？根目录有多少"不知道该不该留"的东西？

## 阶段 1 · 找病灶（逐条回答"是/否 + 证据"）

**A 组 · 重叠与多副本**
- [ ] **1-1 同一事实两处完整写出**：搜同一个数字/同一份清单/同一条规则，是否存在 ≥2 处**各自完整写出**？
      判据：`grep` 命中 ≥2 份手写副本 ⇒ 已在漂移路上。
- [ ] **1-2 文档互相重叠**：有没有两份文档都能回答同一个问题？各写一句"它存在的唯一理由"，写不出的就是重叠。
- [ ] **1-3 规则副本数**：拿一条最重要的禁令去 `grep` 活跃文档，命中 **>2 处** ⇒ 该改指针（1 处权威 + 至多 1 处动作现场）。

**B 组 · 易腐与手写**
- [ ] **1-4 手写易腐数字**：文档里有没有"当前 N 个命令""体积 N KB""主文件 N 行"这类**会自己变化**的声明？
      （注意：解释性注释里引用旧数字，会让门禁匹配到自己 ⇒ 改措辞，不要弱化判定。）
- [ ] **1-5 契约与真值对不上**：数据/接口文档里的字段清单，与代码校验涉及的字段是否**逐一对得上**？缺一个就是"照着文档改会漏"。
- [ ] **1-6 状态标注过期**：`开发中`/`待办`/`临时`/`暂不支持` 这类词，是否**没有版本或日期锚**、且已经过期？
      （实测：一个已发布功能被标成"开发中"，躺过两个版本无人发现。）

**C 组 · 结构与位置**
- [ ] **1-7 无家可归的内容**：工程根、顶层目录、`docs/` 之外，有没有文档/脚本/图片/数据乱放？
      有没有"临时目录"实际承担了长期职责？
- [ ] **1-8 目录是按规则分的，还是按角色分的**：如果一个子目录与父目录的**规则完全相同**（同样只增不改、同样不进扫描），
      那它不该存在（层是角色，不是规则）。
- [ ] **1-9 归档没有身份**：归档文件是否带"历史归档（日期）：不是现状"的横幅？**前几行**有没有？（横幅必须在开头才起作用。）

**D 组 · 交接面**
- [ ] **1-10 "没做完的事"是否有唯一归属**，且与"已完成未发版"**分开**？两件事混成一个清单 ⇒ 每条都要靠脑补判断。
- [ ] **1-11 "下一步"是否第一屏可达**：第一屏里有没有**有序的**接手步骤（而不是只有"有哪些文档"的导航表）？
- [ ] **1-12 上次验证是否留痕**：一条命令能否回答"上次全绿是什么时候"？
- [ ] **1-13 交接指针是否可校验**：在飞条目指向的证据目录，是否有**已经被删/改名**的？

**E 组 · 门禁与强制**
- [ ] **1-14 规则靠什么强制**：每条规则是"能机械判定"（⇒ 应做门禁）还是"靠自觉"？
      铁律条数**多**不是严谨的信号，而是门禁缺失的信号。
- [ ] **1-15 门禁证明过判别力吗**：有没有哪条门禁**从未红过**？（没红过的不算门禁 —— 先注入一次违规试试。）
- [ ] **1-16 门禁有没有写能力边界**：抓得住什么、抓不住什么？不写边界，使用者会以为它万能。
- [ ] **1-17 采不到真值时的行为**：是"红 + 打印无法取得真值"，还是"静默跳过仍打印一致"？后者等于门禁不存在。
- [ ] **1-18 报错是否指路**：判红时有没有告诉人"改哪个文件、跑哪条命令、有几条出路"？

## 阶段 2 · 定优先级（按"接手成本 × 缺陷频次"排，不按"看起来乱不乱"）

- [ ] **2-1 把 1-x 的命中项按下面的顺序归类**（这个顺序不可颠倒，因为后面的依赖前面的）：

  | 顺位 | 做什么 | 前置条件 | 典型收益 |
  |------|--------|---------|---------|
  | 1 | **分层与准入**：给每份文档写"作用/不该写/更新方式"；定白名单 | 无 | 消灭"重叠文档"与"乱放" |
  | 2 | **单源化**：挑最易腐的 2–3 样做生成 + 逐字校验 | 阶段 1 完成 | 消灭"数字/清单漂移" |
  | 3 | **三类归宿**：归档横幅 + 工作产物区出口 + 机器产物声明 | 无 | 历史不再污染活跃视野 |
  | 4 | **交接面**：第一屏接手 N 步 + 在飞清单 + 验证留痕 + 指针校验 | 阶段 1 | 直接把 0-4 的答不上来变成答得上 |
  | 5 | **门禁化**：只做**已经发生过缺陷**的判定，逐条注入证明 | 1–4 | 把"靠自觉"变成"违反即红" |
  | 6 | **常设演练**：每轮一次零上下文接手演练，卡点必须转化 | 全部 | 发现你自己列不出的缺口 |

- [ ] **2-2 圈出本轮**要做的 2–3 项，其余写进"计划/不做"清单（避免一次改太多、无法归因）。
- [ ] **2-3 写下本轮"不做"的项与理由** —— 下一轮接手者会需要它（否则他会重提一遍）。

## 阶段 3 · 改（每项都带验收）

- [ ] **3-1 改动前**：确认锚点唯一命中；对将被改的文件取哈希留存。
- [ ] **3-2 改动中**：一次只做一类（分层 / 单源 / 交接 / 门禁）——混做会让"哪一项起了作用"无法归因。
- [ ] **3-2b 处置散落草稿与过期文档：**两步，顺序不能反**（`SKILL.md` D5）**：
      ① **先抢救"为什么"** —— 逐份做**待遇表**（仍承载当前事实？有没有决策/口径依据？被引用过吗？归宿是哪类？），
         把抽出来的"为什么"写进决策记录/契约；
      ② **再定归宿** —— 结论已被别处承载 → 归档（加横幅）或删；结论还没进契约 → 移进工作产物区并列入"在飞"（带指针）。
      **同主题的草稿合并进 ≤2 个工作目录**（不要一份一个目录），每个目录一个 README 声明死活。
      ⚠️ 反过来做（先归档/先删）= **不可逆的信息损失**。
- [ ] **3-3 新增文档**：写头部元信息块 → 重生成登记表 → 变更记录记一笔（**同步点应当只有 3 处**）。
- [ ] **3-4 每条新门禁**：注入违规 → 确认变红（记报文）→ 撤销 → **复绿**（撤销也要复核，实测曾借此抓到真 bug）。
- [ ] **3-5 改动后**：跑一遍完整验证链；确认耗时**没有明显上涨**（文档类判定应当仍是毫秒级）。

## 阶段 4 · 验收（用阶段 0 的同一把尺子量）

- [ ] **4-1 复量接手成本**：第一屏跳数 / 常见任务读几份 / "上次绿没绿"能否一条命令回答 —— 与 0-5 对照。
- [ ] **4-2 再跑一次只读接手演练**（换一个零上下文会话），与 0-4 的基线对照。
- [ ] **4-3 卡点清零**：每条卡点要么已转化，要么显式"决定不做"。
- [ ] **4-4 写下本轮结论**：哪一项真的降低了成本（给数字）、哪一项没效果（**没效果的也要写**）。
- [ ] **4-5 承诺下一轮**：把第 2 步里没做的项与本次新发现，写进"在飞 / 未收口"清单（带证据指针）。
