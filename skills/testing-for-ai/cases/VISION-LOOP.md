## 0. 闭环全景（本工程视角）

目标：AI 迭代本工程时**全程不出现在用户桌面上**，且验证结论由「执行 + 读图」**双重支撑**，
而不是"跑过了就算数"。

```
┌────────────┐  ① 隐藏离屏窗口（show:false，不弹桌面不抢焦点）
│  AI 改动   │ ─────────────────────────────────────────────┐
└────────────┘                                              ▼
┌──────────────────────────────────────────────────────────┐
│  headless 运行（npm run smoke / verify）                    │
│  ② 虚拟输入注入（真实 DOM MouseEvent/KeyboardEvent）        │
│  ③ 自动截图（capturePage → smoke-shot.png）                │
│  ④ AI 读图（Read 打开 PNG，视觉核对）                       │
│  ⑤ headless 断言判定（冒烟断言清单 + exit 0/1 契约）        │
└──────────────────────────────────────────────────────────┘
              ▲            │
              └── 失败回流（截图+现场 → 定位 → 修复 → 重跑）──┘
```

**六环 + 数据隔离的现状**（证据只给落点，计数见 `docs/VERIFY.md`）：

| 环节 | 状态 | 证据（落点） |
|------|------|-------------|
| ① 离屏运行 | ✅ 已落地 | `main.js` → `createWindow()`（headless 分支）；`scripts/smoke/14-headless-window.js` 断言① |
| ② 虚拟输入 | ✅ 已有 | 各 `scripts/smoke/NN-*.js` 全程 `new MouseEvent/KeyboardEvent` + `dispatchEvent` |

## 1. 已落地：离屏窗口契约（阶段 1，实测）

### 1.1 契约四条（`main.js` `createWindow()`）

```
headless = !!(opts && opts.show === false)
  show: false                     ← 构造期隐藏（smoke / export-image 分支显式传参）
  skipTaskbar: headless           ← 构造选项（见 §2 平台边界）
  backgroundThrottling: !headless ← 隐藏窗口禁节流（否则定时器降频/rAF 暂停 → 旧帧/黑屏）
  paintWhenInitiallyHidden: true  ← 未显示也绘制（capturePage 才读得到真实帧）
```

### 1.2 断言与判别力（`scripts/smoke/14-headless-window.js`）

- **断言①**：smoke 模式下 `isVisible()===false`（不弹桌面不抢焦点）。
- **断言②**：隐藏状态下 `capturePage` 读到**有效帧**（像素统计：非空、`unique`/`range`/`variance` 过阈）。
  判别力已实测：真实界面帧 `unique` 数百、`range≈225`、`variance≈4000`；全黑/全白帧
  `unique=1 / range=0` **必红**。阈值已收敛到单源文件 `scripts/vision/thresholds.js`（见 skill `SKILL.md` 的 **B1**「阈值单源」）。
- 模块 `module.exports.analyzeFrame`，供后续视觉断言复用（L2/L3 的基础）。

### 1.3 读图记录（实测，可复现）

跑一次 `npm run smoke` 后用 Read 打开 `smoke-shot.png`：工具栏（保存/展开/收起/还原视图/命令）、
编辑节点弹窗、关系审计面板、左右两侧导图层级**全部在画面内**，非黑屏非白屏。
（分辨率与哈希随每次运行变化，不在此手写 —— 读图结论应按 skill 的 L4 规范落盘到 `.review/vision/`。）

### 1.4 与通用方法的偏离（本工程特有，换项目请重新判断）

| 偏离点 | 本工程做法 | 通用方法怎么说 |
|-------|-----------|--------------|
| 断言组织 | `scripts/smoke-assertions.js` 入口只做 require + 顺序拼接，断言写在 `scripts/smoke/NN-*.js` 分域文件 | 通用（防单文件膨胀），skill 已吸收 |
| 数据隔离 | 环境变量 `<APP>_PROJECTS_DIR` 指向 `os.tmpdir()` 副本 | 通用（数据根重定向 + 子进程继承）；**只吸收机制，变量名随工程定** |
| 视觉断言位置 | **已独立成 `scripts/vision/`**（`roi-assertions.js` / `thresholds.js` / `record.js`），见 §0 与 §3 | 通用方法建议独立目录 + 阈值单源（本工程**已落地**） |

## 2. 平台 / 本机边界（诚实标注，勿当 bug）

- **`skipTaskbar` 平台边界**：Windows 的任务栏条目只在窗口**真正显示**时创建，`show:false` 的窗口
  本就不会出现在任务栏；而 `isSkipTaskbar()` 对**从未显示过的窗口**查询不稳定（实测返回 `false`）。
  故 headless 核心契约收敛为 `isVisible()===false`，`skipTaskbar` 仅作信息记录（`n/a`）。
  且 `setSkipTaskbar(true)`（事后调用）对未显示窗口无效，**必须走构造选项**。
- **受限沙箱下 Electron 可能完全起不来**：Chromium 的 mojo IPC 需要命名管道，被拒时报
  `FATAL: mojo ... platform_channel.cc ... 拒绝访问 (0x5)`。这是**环境限制**，不是工程缺陷；
  遇到时换不受限环境跑，并显式标注该边界（否则会被误读成"测试挂了"）。
- **本机受限环境下的假失败**：`npm test` 需 `--pool=threads`（默认 forks 池走管道 stdio，会 `spawn EPERM`）；
  `scripts/cli-integration.js` 与 `scripts/doc-facts.js --check` 的子进程捕获同理。
  这类"采不到真值"必须**当红处理**（门禁 G6 已如此实现），不许跳过再宣称通过。
- **`getBitmap()` 已弃用**：Electron 44 起应换 `toBitmap()`（现实现会打 DeprecationWarning，属技术债）。

### 3.1 两处**裁决**（原规格与工程既有约定互斥，已定）

1. **读图记录的落点：按"工作产物"处理，不登记 §5。**
   原规格写「`.review/vision/` **需先在 `ARCHITECTURE.md` §5 登记**」，而 `ARCHITECTURE.md` 明确
   「**工作产物（分析稿、评审稿、读图结论、探针脚本）不是产品文档**：统一放工作产物区、不进 §5 口径」
   ⇒ **同一件事在两份文档里要求相反**。裁决：**以工作产物定义为准**（它也确实是"迭代产物"）。
   ⚠️ **但 `.review/` 会被 G1（编码门禁）扫** ⇒ 记录必须 **UTF-8 无 BOM**（`record.js` 已用 utf8 写；
   **不要**改用 PowerShell 的 `Set-Content`，它会写 BOM）。
2. **读图记录不进验证链（不加门禁）。**
   依据是阶梯自己写的：L4 那一栏的"抓不住"= **"无法自动判定 ⇒ 只能产出证据，不许做门禁"**
   （见 skill `REFERENCE.md` §2.3 的 L4 行，与 `SKILL.md` 的 **B7**）
   ⇒ 给一个自称不可自动判定的层级加门禁是自相矛盾的。
   ⇒ 因此记录的语义是"**本次迭代的证据**"，**不是跨迭代比对键**：哈希绑的是本次截图，
   图一换记录即过期（这不影响它作为证据的价值，但**不能把它当"与上次一致"的判据**）。
3. **不新增 verify 步。** 视觉断言跑在**同一次冒烟引导内、截图之后**（复用同一帧）
   ⇒ 天然满足"先行为、后画面"，且不新增 Electron 启动（冒烟已占全链大部分墙钟，再加一次不可接受）。

### 3.2 方向性说明（别把 L2 当 L1 的替代）
L1（有效帧）与 L2（关键区域）是**叠加**关系：L1 抓"黑屏/白屏/空白页"，L2 抓"整图有效但某关键区空白"。
只做 L1 时"取景漂移"抓不到 —— 那是 L1 的**已知边界**，已由阶段 2 的**尺寸断言**补上。

> **修正记录（旧版失实）**：旧版 W1 写「smoke/export-image 固定窗口尺寸（`1680×1050`，**已落地**）」——
> 实测**不成立**：只有 `--export-image` 分支传了 `1680×1050`，smoke 分支只传 `{show:false}`，
> 走的是窗口**默认尺寸**（实测截图即默认窗口的客户区，非 1680×1050）。
> 即"固定尺寸"对 smoke **未落地**，正是上表阶段 2 的第一项。**别再把默认值当固定值。**
