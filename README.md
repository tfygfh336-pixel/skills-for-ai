# skills-for-ai

给**由 AI 长期开发、维护与迭代**的工程用的三个方法论 skill。三者分工、互不重叠，可单独拷走使用。

| Skill | 管什么 | 不管什么 |
|---|---|---|
| [`architecture-for-ai`](skills/architecture-for-ai/) | **结构选择**：分层与依赖方向、单一逻辑源与薄壳、接口粒度与读取成本上界、数据层并发保护与原子写、可机械取证的结构前提、回滚能力 | 验证体系、文档治理 |
| [`docs-for-ai`](skills/docs-for-ai/) | **文档体系**：该有哪些文档、每份只写什么、单源与生成、交接面、文档门禁 | 代码与数据的结构本身、验证体系 |
| [`testing-for-ai`](skills/testing-for-ai/) | **可验证体系**：验证链分段计时、分层与必跑集合、真值与门禁、门禁自身的单测与判别力证明、界面截图与读图证据 | 结构选择、文档治理、主观质量 |

判据只有一条：**一个零上下文的 AI，能否凭它独立接手一个工程** —— 读懂当初为什么这样设计、现在按什么规范改、改完按什么标准验。

## 用法

把需要的目录拷到你的 skill 加载目录即可，例如：

```bash
cp -r skills/architecture-for-ai ~/.dsh/skills/
```

每个 skill 自足：`SKILL.md` 是决策层（先读），`REFERENCE.md` 是机制层（落地、权衡、失败模式、实测数据），
`cases/` / `checklists/` / `templates/` 是参考实现与可整份拷走的脚本。

## 一个约定：证据强度四档词表

三个 skill 用**同一套四档**给结论标强度。**这段在三份 README 里内容相同** —— 改一处要同批改三处，
否则就是这几个 skill 自己禁止的「第二份会漂移的副本」。

| 记号 | 名字 | 含义 | 换环境会怎样 |
|---|---|---|---|
| 🟢 | 源码级 / 平台契约 | 能从源码、类型声明或官方文档直接读到，是硬约束 | 仍成立，除非上游改契约 |
| 🟡 | 单机实测 | 在一台机器 / 一个版本上跑出来，并留有记录 | **应重测**再引用 |
| 🔴 | 参考实现的选择 | 设计取舍，**不是定律**；条件变了可能反转 | 换栈 / 换场景**应重新判断**，最该被推翻 |
| ⚪ | 未验证 | 只有推理，没有取证 | **必须先验证**才能当依据 |

文中出现的工程名、数字、路径与命令都是**案例与证据**，不是判据、不是要求。
把某个工程的具体选择当成「用本方法就得这么做」，是最常见的误读。
